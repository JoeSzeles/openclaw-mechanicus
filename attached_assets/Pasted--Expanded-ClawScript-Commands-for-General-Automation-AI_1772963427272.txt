### Expanded ClawScript Commands for General Automation & AI Agent Orchestration

Attila, expanding ClawScript from trading-focused to a **general-purpose automation DSL** is a brilliant move — it becomes a "ClawOrchestrator" for OpenClaw agents, tasks, workflows, and integrations. This builds on your existing parser (variables, loops, conditionals, try-catch, AI_QUERY, CLAW_WEB/X, ALERT, SAY_TO_SESSION, WAIT_FOR_REPLY, etc.) to enable:

- **Task Planning**: Define, assign, chain tasks in flows.
- **Agent Management**: Spawn, call, pass data between agents.
- **Skills & Tools**: Call OpenClaw tools, cron, web/serial, file I/O, shell.
- **Workflow Execution**: Execute sub-scripts, publish to canvas, send email/channel.

I added the ones you mentioned, plus more I "missed" but that fit logically (e.g., error logging, parallel execution, webhook listening, data transformation, notification templates, security checks for shell/file). All are realistic with code_execution (for heavy tasks), fs/path/http for file/web/shell, your channels for email/SMS, and OpenClaw's CEO/agent system for orchestration.

The list is grouped, with ~40 new commands (extensive but phased — start with 10–15). Each includes grammar, description, example, and tie-in/wrapper (JS stub for openclaw-tools.cjs or similar).

#### Task Planning & Workflow Commands
These let AI agents plan/show flows, assign tasks, chain them.

- **TASK_DEFINE**  
  Grammar: `TASK_DEFINE "name" WITH "description" [PARAMS "key1,type1;key2,type2"] [BODY ... ENDTASK]`  
  Description: Define a reusable task with params and body (like function, but for workflows).  
  Example: `TASK_DEFINE "analyze_news" WITH "Summarize news" PARAMS "url,string" BODY DEF summary = CLAW_WEB url INSTRUCT "summarize" RETURN summary ENDTASK`  
  Tie-In: Stores in DB as callable; wrapper: function registry in runtime.

- **TASK_ASSIGN**  
  Grammar: `TASK_ASSIGN "task_name" TO "agent_name" WITH args [PRIORITY num]`  
  Description: Assign task to an agent (or "current").  
  Example: `TASK_ASSIGN "analyze_news" TO "researcher" WITH url="news.com.au" PRIORITY 1`  
  Tie-In: SPAWN_AGENT or CALL_SESSION with task prompt.

- **TASK_CHAIN**  
  Grammar: `TASK_CHAIN "task1" THEN "task2" THEN "task3" [ON_ERROR "fallback_task"]`  
  Description: Chain tasks sequentially, pass output as input.  
  Example: `TASK_CHAIN "fetch_data" THEN "analyze" THEN "report"`  
  Tie-In: CHAIN expr (expanded earlier) with agent calls.

- **TASK_PARALLEL**  
  Grammar: `TASK_PARALLEL "task1" AND "task2" AND "task3" [WAIT_ALL true]`  
  Description: Run tasks in parallel, wait for all or any.  
  Example: `TASK_PARALLEL "scan_x" AND "scan_web" WAIT_ALL true`  
  Tie-In: Promise.all in generated JS + code_execution for concurrency.

- **TASK_SHOW_FLOW**  
  Grammar: `TASK_SHOW_FLOW "workflow_name" [FORMAT "png/json"]`  
  Description: Generate visual flow of tasks (publish to canvas or export).  
  Example: `TASK_SHOW_FLOW "daily_routine" FORMAT "png"`  
  Tie-In: code_execution with graphviz/matplotlib for PNG, or JointJS export.

- **TASK_LOG**  
  Grammar: `TASK_LOG "message" [LEVEL "info/warn/error"]`  
  Description: Log task progress (to DB/logs).  
  Example: `TASK_LOG "Task started" LEVEL "info"`  
  Tie-In: Your existing log function + DB insert.

#### Agent & Orchestration Commands (Expand Existing)
- **AGENT_SPAWN**  
  Grammar: `AGENT_SPAWN "name" WITH "prompt" [SKILLS "skill1,skill2"] [TIMEOUT min]`  
  Description: Spawn sub-agent with specific skills/tools.  
  Example: `AGENT_SPAWN "analyzer" WITH "Analyze this data" SKILLS "code_execution,web_search"`  
  Tie-In: Your CEO spawn wrapper.

- **AGENT_CALL**  
  Grammar: `DEF result = AGENT_CALL "agent_name" "command" WITH args`  
  Description: Call running agent with command, get result.  
  Example: `DEF data = AGENT_CALL "fetcher" "get_news" WITH url="site.com"`  
  Tie-In: CALL_SESSION expanded.

- **AGENT_PASS**  
  Grammar: `AGENT_PASS "data_var" TO "agent_name"`  
  Description: Pass data between agents.  
  Example: `AGENT_PASS analysis TO "reporter"`  
  Tie-In: SAY_TO_SESSION or DB share.

- **AGENT_TERMINATE**  
  Grammar: `AGENT_TERMINATE "agent_name" [REASON "text"]`  
  Description: Kill sub-agent.  
  Example: `AGENT_TERMINATE "analyzer" REASON "Task complete"`  
  Tie-In: Your process manager.

#### Skills & Tools Commands (Call OpenClaw Skills)
- **SKILL_CALL**  
  Grammar: `DEF result = SKILL_CALL "skill_name" WITH args`  
  Description: Call any OpenClaw skill (e.g., ig-market-data, backtest).  
  Example: `SKILL_CALL "ig-market-data" WITH epic="AUDUSD"`  
  Tie-In: proxyRequest to skill APIs.

- **CRON_CREATE**  
  Grammar: `CRON_CREATE "name" SCHEDULE "cron_pattern" RUN "command_block"`  
  Description: Create cron job for recurring tasks.  
  Example: `CRON_CREATE "daily_backup" SCHEDULE "0 0 * * *" RUN "FILE_BACKUP all"`  
  Tie-In: code_execution with node-cron lib (or setInterval fallback).

- **CRON_CALL**  
  Grammar: `CRON_CALL "name" [NOW true]`  
  Description: Trigger cron job manually.  
  Example: `CRON_CALL "daily_backup" NOW true`  
  Tie-In: Cron trigger.

- **WEB_FETCH**  
  Grammar: `DEF data = WEB_FETCH "url" [METHOD "GET/POST"] [BODY "json"]`  
  Description: HTTP fetch (beyond CLAW_WEB).  
  Example: `WEB_FETCH "api.com" METHOD "POST" BODY "{key: value}"`  
  Tie-In: http.request.

- **WEB_SERIAL**  
  Grammar: `DEF data = WEB_SERIAL "port" BAUD rate [READ/WRITE "data"]`  
  Description: Serial port I/O (for hardware like Arduino in Brisbane projects).  
  Example: `WEB_SERIAL "/dev/ttyUSB0" BAUD 9600 READ`  
  Tie-In: code_execution with pyserial (Python serial lib).

#### File & Data Commands
- **FILE_READ**  
  Grammar: `DEF content = FILE_READ "filename" [FORMAT "text/csv/json"]`  
  Description: Read file.  
  Example: `FILE_READ "data.csv" FORMAT "csv"`  
  Tie-In: fs.readFileSync + code_execution pandas for CSV/JSON.

- **FILE_WRITE**  
  Grammar: `FILE_WRITE "filename" CONTENT data [APPEND true]`  
  Description: Write file.  
  Example: `FILE_WRITE "log.txt" CONTENT "Entry: " + var APPEND true`  
  Tie-In: fs.writeFileSync.

- **FILE_EXECUTE**  
  Grammar: `DEF result = FILE_EXECUTE "filename"`  
  Description: Run file as ClawScript or shell.  
  Example: `FILE_EXECUTE "sub_script.cs"`  
  Tie-In: parseAndGenerate + eval, or child_process for shell.

- **DATA_TRANSFORM**  
  Grammar: `DEF transformed = DATA_TRANSFORM data USING "operation" [PARAMS "key=value"]`  
  Description: Transform data (filter, map, reduce, sort).  
  Example: `DATA_TRANSFORM trades USING "filter" PARAMS "pnl > 0"`  
  Tie-In: code_execution numpy/pandas.

#### Communication & Notification Commands
- **CHANNEL_SEND**  
  Grammar: `CHANNEL_SEND "channel" MESSAGE "text" [OPTIONS "key=value"]`  
  Description: Send to Telegram/SMS/voice/email/Discord.  
  Example: `CHANNEL_SEND "email" MESSAGE "Report" OPTIONS "to=you@email.com"`  
  Tie-In: Your channels wrapper expanded.

- **EMAIL_SEND**  
  Grammar: `EMAIL_SEND TO "address" SUBJECT "text" BODY "content" [ATTACH "file"]`  
  Description: Send email.  
  Example: `EMAIL_SEND TO "me@gmail.com" SUBJECT "Daily Summary" BODY summary`  
  Tie-In: code_execution with smtplib (Python email).

- **PUBLISH_CANVAS**  
  Grammar: `PUBLISH_CANVAS "page_name" FROM "data_var" [FORMAT "html/json"]`  
  Description: Generate/publish page to your canvas dashboard.  
  Example: `PUBLISH_CANVAS "status" FROM state FORMAT "html"`  
  Tie-In: fs.writeFile to .openclaw/canvas/.
