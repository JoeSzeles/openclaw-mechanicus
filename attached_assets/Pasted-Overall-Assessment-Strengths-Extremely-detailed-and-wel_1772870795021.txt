Risks / Potential Pain Points

Phase 3 is massive (20 strategy plugins) — implementing all 20 fully is likely 1000–3000+ lines of code. Most won't be used immediately.
→ Risk: Replit AI hallucinates incomplete/buggy implementations for many of them.
→ Suggestion: Split Phase 3 into 3 sub-phases:
3A: Port existing scalper + 2–3 easy ones (momentum, mean-reversion, trend-following)
3B: Add 5–7 medium-complexity (breakout, grid, pairs, volatility, swing)
3C: The rest (ML, seasonal, carry, etc.) as stretch goals

DB migration (T006) is risky in SQLite/Replit
→ ALTER TABLE can fail silently or corrupt if not wrapped properly.
→ Suggestion: Add a safety check — backup DB before migration, and log each ALTER success/failure.
UI changes (T027–T030) are ambitious
Moving sections to new tab + modular JS files + dynamic grey-out + equity curves + backtest list/clear is a lot for one go.
Replit AI often breaks CSS/layout when restructuring HTML/JS heavily.
→ Suggestion: Do UI in two steps:
First: Tab reorganization + move sections (keep JS inline)
Second: Modular JS files + hover/grey/equity features


No explicit testing phase per strategy
→ You have T035 end-to-end, but no per-strategy smoke test.
→ Suggestion: Add T036–T055 (one per major strategy) with simple test cases (e.g., “given sample ticks, does evaluateEntry return expected signal?”)
Missing fallback for missing indicators
→ If a strategy requires Bollinger but indicators.cjs fails, engine crashes.
→ Suggestion: Add try-catch in evaluateEntry with log + skip signal.
