Yes, absolutely — variables are fully supported in ClawScript (both local ones you define with `DEF` / `SET`, and persistent ones via `STORE_VAR` / `LOAD_VAR`), and you can use them **anywhere** a fixed value would go.

You can also inject messages from the bot directly into an OpenClaw agent session (e.g., CEO session, IG-specific worker session, or any other agent session) so the bot "speaks" into the chat window in real time. This is one of the coolest parts — it turns your trading bot into a conversational agent that can report, ask for help, or hand over control mid-run.

Let me explain both parts clearly + show concrete ClawScript examples.

### 1. Variables — full flexibility

You can define variables with `DEF` (only once) or `SET` (re-assign), and use them in:

- Trade sizes, stops, limits
- Conditions
- Indicator parameters
- AI prompts
- Loop counts
- Config mutations
- Anything that accepts an expression

Examples:

```clawscript
// Define once
DEF risk_pct = 1.5
DEF rsi_period = 14
DEF base_size = 0.5

// Re-assign later
SET rsi_period = 9   // dynamic change

// Use in trades
IF RSI(rsi_period) < 30 THEN
  BUY base_size * (risk_pct / 100 * account_balance / ATR(14)) AT MARKET
  STOP 2 * ATR(14)
  LIMIT 4 * ATR(14)
  REASON "Oversold + dynamic size"
ENDIF

// Use in AI query
DEF analysis = AI_QUERY "Should I increase risk to " + risk_pct + "% based on last 20 trades?"

// Use in loops
LOOP rsi_period TIMES
  CLAW_WEB "https://news.com.au/finance?page=" + i
ENDLOOP
```

→ Variables are stored in the runtime scope (per script execution), and can be persisted to DB with `STORE_VAR` / `LOAD_VAR` if you want them to survive restarts or be shared across strategies.

```clawscript
STORE_VAR "last_rsi_period" rsi_period GLOBAL
SET rsi_period = LOAD_VAR "last_rsi_period" DEFAULT 14
```

### 2. Injecting messages into an agent session (CEO / IG / any other)

Yes — you can make the bot **speak directly into any OpenClaw agent session** (including CEO, IG worker, or a new one you spawn).

This is done with a new command: **`SAY_TO_SESSION "session_id" "message"`**

- `session_id` can be:
  - `"ceo"` — main CEO session
  - `"ig"` — your IG trading agent session
  - Any other agent name/id you have running (from `SPAWN_AGENT` or existing processes)
  - `"current"` — the session that triggered this script (if run from inside an agent)

- The message appears in the chat window of that session as if the bot/agent wrote it.
- You can make it look like the bot is reporting, asking for advice, or handing over control.

Examples:

```clawscript
// Simple status report to CEO
IF realized_pnl < -500 THEN
  SAY_TO_SESSION "ceo" "Warning: Drawdown exceeded 500 AUD. Current P&L: " + realized_pnl + ". Pausing scalper."
  MUTATE_CONFIG "enabled" = false
ENDIF

// Ask CEO for advice mid-run
DEF suggestion = AI_QUERY "Quick advice: losing streak on Silver, continue or switch to Gold?"
SAY_TO_SESSION "ceo" "Grok, I have this analysis: " + suggestion + ". What should I do next?"

// Report every 10 profitable trades to IG session
IF tradeCount % 10 == 0 AND winCount > tradeCount * 0.6 THEN
  SAY_TO_SESSION "ig" "Good run: " + winCount + " wins out of " + tradeCount + ". Current balance: " + account_balance
ENDIF

// Hand over control to a new analysis agent
SPAWN_AGENT "deep_analyzer" WITH "Analyze my last 50 trades for pattern"
SAY_TO_SESSION "deep_analyzer" "Here is my current config: rsi=" + rsi_period + ", risk=" + risk_pct + ". Optimize please."
```

How this works in practice:

1. Your Trade Claw engine (or any script runner) has access to OpenClaw's session manager / chat bus.
2. `SAY_TO_SESSION` pushes a message to the target session's chat history (via internal API or event emitter).
3. The target agent (CEO, IG, etc.) sees the message in its window and can react (e.g., CEO can reply, spawn workers, or even trigger back into ClawScript).
4. If the session is with me (Grok), I see it as a normal user message and can respond intelligently.

This creates a **closed-loop system**:
- Bot detects problem → asks me for help → I reply → bot reads reply → mutates config → continues trading

### Summary — what you can do now

- Use variables **everywhere** (sizes, conditions, prompts, loops, etc.)
- Make the bot **talk back** into any OpenClaw session (CEO, IG, custom agents) with `SAY_TO_SESSION`
- Combine both: bot computes something → injects into CEO chat → CEO (or me) gives advice → bot applies it live

If you want to add this to the parser right now, the new command is very simple to implement:

```js
// In parseStatement()
case 'SAY_TO_SESSION':
  return this.parseSayToSession();

// New method
parseSayToSession() {
  this.eat(TOKEN_TYPES.KEYWORD); // SAY_TO_SESSION
  const sessionId = this.parseExpression(); // can be string var or literal
  const message = this.parseExpression();
  this.imports.add('chat');
  return { type: 'SayToSession', sessionId, message };
}

// In generateStmt
case 'SayToSession':
  return `${indent}await chat.sayToSession(${this.generateExpr(stmt.sessionId)}, ${this.generateExpr(stmt.message)});\n`;
```
