# OpenClaw Cloud

## Overview
OpenClaw Cloud is an online, hosted version of OpenClaw, serving as a multi-channel AI gateway with extensible messaging integrations. It runs on Replit as a persistent web service with a browser-based Control UI dashboard. This platform centralizes the management of AI chat sessions, channels, agents, models, and configuration. Its primary purpose is to act as a central "CEO" dispatching tasks to local "Worker Bee" OpenClaw instances, eliminating the need for local installations.

## User Preferences
- **Workflow restart**: Always use `kill -9 1` to force-kill before restarting. Never use pkill or soft kills -- they hang.
- `start.sh` has `trap 'kill -9 1' TERM INT` to support clean restarts.
- **Persistent storage**: All OpenClaw data must persist across restarts and be manually clearable by deleting `.openclaw/`.
- **Config seeding**: `start.sh` only copies seed config if `.openclaw/openclaw.json` doesn't exist, to avoid overwriting user changes.
- **Worker dispatch**: Only `@WorkerName` (with @ symbol) should trigger dispatch -- never plain name mentions.
- **Gateway session key**: The CEO proxy resolves `gwSessionKey` from the gateway hello response's `snapshot.sessionDefaults.mainSessionKey` (e.g., `agent:ceo:main`), NOT from a hardcoded `agent:main:main` fallback. This ensures worker message injection (`chat.inject`) targets the correct session that the UI is viewing.

## System Architecture
OpenClaw Cloud employs a "CEO Proxy + Gateway" architecture, where two components run within a single workflow: a CEO Proxy handling API routes and proxying other requests, and an OpenClaw Gateway serving the Control UI and managing WebSocket connections.

### Key Features:
-   **Login Authentication**: Secures access with username/password, supporting persistent sessions and selective authentication bypass for specific endpoints.
-   **CEO/Worker Bee System**: The Replit instance acts as a CEO, coordinating tasks for local OpenClaw Worker Bee instances. This includes worker registration, API key management, task dispatch, file exchange, and a dedicated Workers Dashboard UI.
    -   **Agent Chat Bridge**: Provides an OpenAI-compatible endpoint for worker bees to access CEO's AI capabilities.
    -   **Inter-Agent/Worker Communication**: Any agent or user can address any other agent or worker via `@Name` mentions. The proxy intercepts these from chat events, dispatches tasks to workers or injects messages into agent sessions. User @mentions dispatch directly without CEO relaying. Workers can also @mention other workers or @CEO.
    -   **Shared Space**: A common folder for file sharing among all agents, accessible via REST API and a web UI file browser.
    -   **CREW.md Auto-Sync**: Automatically updates a `CREW.md` file with live worker status for the CEO agent.
-   **Config Page**: A unified web UI for managing AI Models and IG Trading configurations.
-   **Persistent Storage**: All OpenClaw data is stored persistently in the `.openclaw/` directory.
-   **Canvas Static File Serving**: Serves dynamic HTML dashboards and reports from a dedicated canvas directory, supporting a manifest system for page discovery. HTML files are served with `no-cache` headers to ensure browsers always load the latest version.
-   **Auto-Token Injection**: Automatically injects the gateway authentication token into the Control UI.
-   **Process Manager & Bot Registry**: A web UI for managing ad-hoc and registered bots, including start/stop controls and auto-restart capabilities for bots residing in `skills/bots/`. Bot API (`/api/bots`) is in the bearer-token whitelist for dashboard access.
-   **IG Trading Bot** (`skills/bots/ig-trading-bot.cjs`): Autonomous trading bot that reads strategies from `ig-strategy.json`, evaluates entry conditions against live prices, runs proof-read checks, and opens positions via the proxy API. Integrates with strategy attach/detach/pause APIs — auto-attaches dealId after opening a position, auto-detaches when position closes. Supports `--test` flag for dry runs. Respects live safety checks (`allowLive` flag), profile change detection, risk limits, and max open positions. Entry logic: `entryBelow` means "buy when price drops to or below X" (BUY direction); `entryAbove` means "sell when price rises to or above X" (SELL direction). Duplicate position check respects `allowDuplicatePositions` from proof-read config. Strategy templates available in dashboard for quick creation — new strategies from templates always default to **disabled** to prevent accidental trades.
-   **IG Signal Monitor** (`skills/bots/ig-signal-monitor.cjs`): Price monitoring bot that polls instrument prices, detects signals (momentum, breakout patterns), and writes alerts to `ig-alerts.json`. The trading bot reads these alerts as additional trade confirmation.
-   **Watched Instruments & Trading Panel**: The IG Dashboard features a tab-based instrument watchlist with live prices, market status indicators, and an instrument search modal. Users can search IG markets, add/remove instruments from the watchlist, and trade directly. The Deal panel supports BUY/SELL with size, stop distance, limit distance, and force open/net off options. The Order tab supports limit/stop orders with price level. The Info tab shows instrument details (min size, contract size, slippage, margin). API endpoints: `GET /api/ig/watchedlist`, `POST /api/ig/watchedlist` (add), `DELETE /api/ig/watchedlist/:i` (remove). Watchlist is stored in `ig-monitor-config.json` instruments array.
-   **Interactive Price Charts**: TradingView Lightweight Charts v4.1.3 renders candlestick OHLC charts for the selected instrument with selectable timeframes (1M, 5M, 15M, 1H, 4H, 1D, 1W). Green/red candles with dark theme matching the dashboard (#161b22 bg, #30363d grid). Charts support native scroll-to-zoom and drag-to-pan. Data fetched from `GET /api/ig/pricehistory/{epic}?resolution=...&max=...`. **Data Points Selector**: Dropdown next to timeframe tabs lets users choose 100/250/500/1000/2500 candles (default 250). **Client-Side Cache**: Price data is cached by epic:resolution:maxPoints with 60s TTL (intraday) or 300s (daily/weekly). **Zoom Preservation**: Dashboard auto-refresh updates price lines and markers without recreating the chart, preserving the user's zoom/pan state. When timeframe changes, the visible range is saved and restored after chart recreation. **IG API v2 Path Format**: The proxy uses path-based v2 format (`/prices/EPIC/RESOLUTION/NUMPOINTS` with `Version: 2` header) for single-request full datasets; falls back to v3 query-based pagination when date range params are specified. **Price Line Annotations**: Open position levels shown as price lines (yellow entry, red SL dashed, green TP dashed) and strategy triggers (orange dotted). **Bot Trade Markers**: Scalper trade entries (green arrowUp for BUY, red arrowDown for SELL) and exits (circle colored by P&L) shown on chart from cached trade history. **Backtest Markers**: Backtest trade entries/exits shown as purple squares and circles, distinct from live trade markers. **Click Navigation**: Clicking an open position's market name or a streaming instrument name in their tables navigates to that instrument's chart tab (auto-adds to watchlist if needed). **Auto-Add Streamed Instruments**: All actively streamed instruments are automatically added to the watchlist tabs on first load. **Open in New Window**: Each watchlist tab has a ⧉ button to open a standalone chart-only window via `?chart=EPIC&tf=HOUR` query params (extracts chart to full-screen fixed position, hides all other dashboard elements).
-   **Deal Strategy Selector**: The Deal panel includes a strategy dropdown below the Place Deal button. Filters to show only strategies matching the selected instrument (excluding already-linked strategies). Selecting a strategy auto-fills stop distance, limit distance, size, and direction. After a successful trade, the strategy is automatically attached to the new deal via the attach API.
-   **Strategy Management Dashboard**: The IG Dashboard (`ig-dashboard.html`) provides full CRUD controls for bot trading strategies via live API (`/api/ig/strategies`). Features: toggle individual strategies on/off, inline edit (entry level, stop/limit distances, size, name), delete strategies, master bot enable/disable switch, bot process start/stop buttons, "Add Strategy" button (form modal with instrument search), and strategy templates (quick-add with safe disabled defaults). Strategies can be attached to open positions via `dealId` and paused/resumed independently. Open positions show a Strategy dropdown for linking. Open positions can be edited (stop/limit levels) and closed directly from the dashboard. Strategies can be saved as reusable templates. API endpoints: `GET /api/ig/strategies`, `POST /api/ig/strategies` (create), `PUT /api/ig/strategies/:i`, `DELETE /api/ig/strategies/:i`, `POST /api/ig/strategies/:i/toggle`, `POST /api/ig/strategies/:i/attach`, `POST /api/ig/strategies/:i/detach`, `POST /api/ig/strategies/:i/pause`, `POST /api/ig/strategies/global`. Dashboard uses modular JS files: `ig-strategy-manager.js` (strategy attach/detach/pause/add logic), `ig-live-prices.js` (live price updates). Backup stored in `ig-dashboard-backup/`.
-   **Trade Proof Reader Config**: Editable proof reader thresholds via dashboard and API (`GET /api/ig/proofread`, `PUT /api/ig/proofread`). Controls: max price staleness, spread limits (high/low with mid threshold), min risk:reward ratio, max risk % of balance, max entry deviation %, allow duplicate positions, require stop-loss, require take-profit. Config stored in `.openclaw/ig-proofread-config.json`.
-   **IG API Proxy**: Full-featured proxy for IG Group Trading API covering ALL IG operations: positions (open/close/update), working orders (create/update/delete), market search, price history, watchlists, activity/transaction history, and session management. Handles authentication automatically with centralized session management (4-minute proactive token refresh). All bots and agents route through this single proxy session — bots via `http://localhost:5000/api/ig/...`, agents via `https://$REPLIT_DEV_DOMAIN/api/ig/...` (agents MUST use the public URL because `web_fetch` blocks localhost due to SSRF protection). Market data responses are cached for 30 seconds to prevent IG rate limit errors. See `skills/ig-trading/IG-COMMANDS.md` for complete endpoint reference. Includes a multi-layered trade proof reader for risk mitigation.
- **Agent Workspace Rules**: Agents (CEO and IG) are strictly forbidden from using `localhost` or direct `curl`/`web_fetch` for authenticated endpoints (which require a session cookie). They must use dedicated pre-authenticated tools (e.g. `get_account_balance`). Agents must always use the public URL `https://openclaw-mechanicus.replit.app/` in communications and never mention `localhost`. This is documented in `AGENTS.md` in both the workspace templates and active agent directories.
- **Independent Live Streaming**: Lightstreamer architecture: **Active profile (demo)** connects to `demo-apd.marketdatasystems.com` for L1 instrument price data. **Live profile (BVOLN)** connects separately to `apd.marketdatasystems.com` ONLY for `ACCOUNT:` level data (balance, P&L, margin). Both accounts are CFD-only — if L1 subscription is rejected ("Invalid account type"), hybrid REST polling (3s interval) automatically activates as fallback. The `__ACCOUNT__` key in streamedPrices is filtered from the instruments API. The live streaming token refresh never kills the main L1 connection. `GET /api/ig/stream/prices` returns `{streaming, polling, method, prices}` — `streaming=true` means Lightstreamer L1 is active, `polling=true` means REST fallback. `GET /api/ig/stream/status` returns `{priceSource, priceMethod, hybridPolling, liveAccountClient}` — `priceMethod` is human-readable ("LIGHTSTREAMER L1" or "REST POLLING (every 3s)").
-   **Price Feed Dashboard**: The IG Dashboard "Price Feed" section shows a prominent colored banner: green "LIGHTSTREAMER L1 REAL-TIME" when L1 works, blue "REST API POLLING" when using fallback. Badge shows `LIGHTSTREAMER (N)` or `REST POLL (N)`. Per-instrument table with bid/offer/mid, market status, data age, update counts.
-   **Ultra-Fast Scalper Engine** (`skills/bots/ig-scalper-engine.cjs`): Event-driven scalping bot that hooks directly into the Lightstreamer `onItemUpdate` callback inside `ceo-proxy.cjs` for zero-latency price access. Reacts to every tick — no polling loop. Maintains rolling tick buffers per instrument and calculates micro-momentum. Reads higher-timeframe bias from `ig-alerts.json` (signal monitor). Bypasses the proof reader for speed. **Config stored in PostgreSQL** (tables: `scalper_config` for engine settings, `scalper_strategies` for per-strategy settings, `scalper_trades` for trade log). DB access via `skills/bots/ig-scalper-db.cjs`. Fallback template: `.openclaw/ig-scalper-defaults.json` (read-only). **ALL settings are per-strategy** — no global defaults. Each strategy has its own: cooldownMs, tickWindow, maxOpenPositions, minSize, maxSize, profitTarget, trailingStop, warmupMs, minMomentumPct, and RSI/EMA/MACD indicator settings. Risk controls: budget cap (max capital), max drawdown (auto-stop kill switch), max margin %, break-even buffer (min move > spread × buffer). **Warmup period** (`warmupMs`, default 60s): Bot observes price data without trading after startup, giving indicators time to accumulate data. **Technical Indicators** (optional confirmation filters per strategy): RSI (Wilder's smoothing with tick downsampling via `downsampleTicks()` to prevent wild swings from raw ticks; blocks BUY when overbought, SELL when oversold), EMA crossover (short/long EMA trend confirmation), MACD histogram (momentum direction confirmation). All indicators block on insufficient data when enabled. Tracks realized P&L, win/loss count, win rate. Trade log persisted in `scalper_trades` DB table. Auto-starts with Lightstreamer if `enabled: true`. Strategies support `direction: BOTH` for bi-directional scalping. `resetStats()` clears all strategy `dealId` fields to prevent stuck strategies. Strategy IDs are DB primary keys (integers), not array indices. API endpoints: `GET/PUT /api/ig/scalper`, `GET /api/ig/scalper/status`, `POST /api/ig/scalper/start|stop|reset`, `GET/POST /api/ig/scalper/strategies`, `PUT/DELETE /api/ig/scalper/strategies/:id`, `POST /api/ig/scalper/strategies/:id/toggle`. Dashboard section in `ig-dashboard.html` with 5-second refresh cycle for real-time P&L. Dashboard has separate "Edit Engine" (budget, maxDD) and per-strategy edit panels (click any strategy row to edit all its settings inline including indicators).
-   **Chat Rich Media**: Supports inline iframe embeds for canvas pages and enhanced markdown tables in the chat UI.
-   **Navigation Bar**: Injected navigation for easy access to different sections of the platform.
-   **Public Canvas Data Endpoints (No Auth)**: Scalper trades, bot logs, alerts, strategy/scalper/monitor configs are served as JSON snapshots at `/__openclaw__/canvas/`. Scalper data (`ig-scalper-config-snapshot.json`, `all-scalper-trades-data.json`) is generated from the PostgreSQL database; other configs are copied from their JSON source files. Key files: `ig-dashboard-snapshot.json` (comprehensive live snapshot with account balance, prices, scalper status — updated every 30s), `all-scalper-trades-data.json` (from DB), `ig-bot-log-snapshot.json`, `ig-alerts-snapshot.json`, `ig-strategy-snapshot.json`, `ig-scalper-config-snapshot.json` (from DB), `ig-monitor-config-snapshot.json`. HTML pages: `all-scalper-trades.html` (formatted trade history with filters and stats). All served at `/__openclaw__/canvas/`.
-   **Canvas Config Write API (API Key Protected)**: Agents can read configs freely (GET = no auth) and write configs (POST/PUT) with `CANVAS_API_KEY` via `/__openclaw__/canvas/api/`. Routes: `GET/POST/PUT config/scalper-config`, `config/strategy`, `config/monitor-config`, `config/proofread-config`. POST merges (patches) existing config, PUT replaces entirely. Also: `GET scalper/status` (no auth), `POST scalper/start|stop|reset` (requires key). API key passed via `X-Api-Key` header, `?key=` param, or `Authorization: Bearer` header. Key stored as `CANVAS_API_KEY` env secret. CORS enabled. Logs writes as `[canvas-api]`.
-   **Dashboard Tabs**: The IG Dashboard has three top-level tabs — Dashboard (main trading UI), Bots (scalper strategies with backtest), Backtest (placeholder). Tab switching via `switchDashTab()`.
-   **Scalper Engine Timeframe**: The scalper engine supports per-strategy timeframe selection. When `timeframe=TICK` (default), it evaluates on every incoming tick from Lightstreamer (existing behavior). When set to a candle timeframe (SECOND, MINUTE, MINUTE_5, etc.), it aggregates incoming ticks into OHLC candles and only evaluates entry signals when a candle period closes. Candle close prices are used as pseudo-ticks for momentum calculation and indicator evaluation. This makes backtesting and live trading use the same timeframe logic. Available values: TICK, SECOND, MINUTE, MINUTE_5, MINUTE_15, HOUR, HOUR_4, DAY. State: `candleBuffers` and `currentCandles` track in-progress and completed candles per epic:timeframe pair.
-   **Scalper Backtest Engine** (`skills/bots/ig-scalper-backtest.cjs`): Per-strategy backtest engine that simulates scalper entry logic against historical OHLC candle data. Uses candle close prices as tick proxies. Replicates the scalper's momentum detection, indicator filters (RSI/EMA/MACD), cooldown, and stop/limit/trailing-stop exits. **Date-range stitching**: For large datasets (>2000 candles), fetches in batches of 2000 with 1.5s inter-batch delay, each batch using `to` parameter set to the earliest timestamp of the previous batch. Deduplicates and sorts chronologically. Supports up to 10,000+ candles. Results stored in `scalper_backtests` DB table with: summary stats (trades, win rate, P&L, max drawdown, Sharpe ratio), individual trade details (JSONB), and config snapshot. API endpoints: `POST /api/ig/scalper/strategies/:id/backtest` (run + save), `GET /api/ig/scalper/strategies/:id/backtests` (history), `GET /api/ig/scalper/backtests/:id` (detail). Dashboard UI: BT button per strategy opens modal with timeframe/candle-count selector (250-10000), results shown in collapsible panel with summary stats grid and expandable trade list. Backtest trade markers overlay on chart as purple squares (entries) and circles (exits), distinct from live trade markers.
-   **IG API Data Limits**: The proxy uses the IG v2 path-based format (`/prices/EPIC/RESOLUTION/NUMPOINTS` with `Version: 2` header) which returns all requested candles in a single response (no pagination). When `from`/`to` date parameters are specified, falls back to v3 query format with automatic page aggregation (20 items/page, 200ms delays). V2 response uses `bid`/`ask` fields; dashboard calculates mid-price from `(bid+ask)/2`. Server-side price data cached (30s TTL via `igCacheSet`). Client-side cache: 60s (intraday), 300s (daily/weekly). Max available candles per timeframe: ~10,000 for MINUTE, ~5,000 for HOUR, ~2,000 for DAY (varies by instrument and market hours). Rate limit: ~10,000 API calls per allowance window (resets on rolling basis). Demo accounts have a separate historical data allowance that can be exhausted — dashboard shows a clear error message when this happens. The backtest engine works around large data needs by stitching multiple date-range requests (2000 candles per batch, 1.5s delays).
-   **P/L Calculation**: `P&L = priceDiff × size × plMultiplier` where `plMultiplier = valueOfOnePip × scalingFactor` (from IG's `/markets/{epic}` response). Universal across all instrument types — FX, indices, commodities, crypto, shares. `contractSize` is NOT the correct multiplier (e.g. Silver A$1 has contractSize=100 but plMultiplier=1). Full reference with verified data for all instrument categories: `skills/ig-trading/IG-PL-CALCULATION.md`. The proxy enriches positions with `plMultiplier`, `valueOfOnePip`, `contractSize`, and `scalingFactor`. Risk calculations in both bots also use `plMultiplier`.
-   **Bot Optimization Workflow**: Sub-agents read cached trade data from canvas JSON endpoints (no auth, no rate limits), analyze per-epic performance, backtest against 3-day price history, refine scalper config variables, and log results to `SCALPER_Logbook.md`.
